# Skills Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use subagent-driven-development (recommended) or executing-plans to carry out this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `dish-skills`:
- skills in the config store, under `skills/<name>/SKILL.md`;
- each dish agent offered its role's skills through dsh's skill registry;
- **Settings → Skills**: edit, check, default diff and reset, new, delete, history;
- 18 shipped skills adapted from obra/superpowers;
- role prompts that name their skills;
- default upgrades for documents that are still unedited.

**Architecture:**
- **Host plugin.** `dish-skills` provides the `dishSkills` service. `dishConfig` is optional: with the store, the plugin claims `skills/` and seeds the defaults; without it, the shipped defaults are served.
- **Global provider.** Registered whenever `skills` is present. It lists every skill as menu-only, so a model is never offered one through it.
- **Agent providers.** An `agent/created` listener registers a provider on each agent of a configured preset, in that agent's own layer. It offers the agent's role's skills.
- **Defaults.** `dishConfig.seed` gains `replace`, so stored defaults that are still unedited move to new texts.
- **The page.** A Typert remote serves the Skills page, which reuses `dish-config`'s remote for history and live updates, as Prompts does.

**Tech Stack:** TypeScript (Node 24 type stripping, erasable syntax only), `node --test`, Cordis, dsh 0.2.0-rc.2 (`@deepseek-ai/dsh-skill`, `dsh-scope`, `dsh-agent`, `dsh-agent-preset-registry`), `js-yaml`, React 18 (client), esbuild (client bundle via dish-kit).

**Spec:** [docs/specs/skills.md](../specs/skills.md). Read it first; this plan argues from it. Model the code on `plugins/prompts`, which has the same shape. The [prompts plan](2026-10-01-prompts.md) has the conventions.

## Global Constraints

- Everything in the prompts plan's constraints still holds:
  - Node 24, no build step for server code;
  - erasable syntax;
  - `@deepseek-ai/*` runtime imports only from packages declared under both `peerDependencies` (`^0.2.0-rc.2`) and `devDependencies` (`0.2.0-rc.2`);
  - tests in `<package>/test/*.test.ts`;
  - every task ends with `pnpm typecheck && pnpm test` passing and one commit.
- **Check exit codes.** Never pipe the gate through `tail` or `head`.
- **Branch `skills`.** Task worktrees are cut from it. Humans merge.
- **Package:** `plugins/skills`, name `dish-skills`. Exports `"."` → `./src/index.ts` and `"./client"` → `./lib/client.js`.
  - Dependencies: `dish-config` and `dish-kit` (`workspace:*`), `js-yaml ^4.1.0`, and `@deepseek-ai/schemastery ~3.18.4`, which prompts already uses.
  - Dev dependency: `@types/js-yaml`.
  - `yaml` at the root is for scripts only. Use `js-yaml`, as crew and judge do.
- **Store path:** `skills/<name>/SKILL.md`.
  - `<name>` matches `^[a-z0-9]+(?:-[a-z0-9]+)*$` and is at most 64 characters.
  - One namespace claim, prefix `skills/`, agent policy `propose`.
- **Roles:** names match `^[a-z][a-z0-9-]*$`. The known roles are `main` plus the roles in crew's settings when `dishCrew` is present. Otherwise they are `main`, `architect`, `coder`, `reviewer`, `researcher`, `ops`, `writer`.
- **Skill limits:**
  - description at most 1024 characters;
  - a warning, not a refusal, above 8000 characters of document;
  - the dsh legacy keys `disableModelInvocation`, `modelInvocable` and `userInvocable` are refused.
- **Providers:**

  | Provider | Rank | Lists | Source |
  |---|---|---|---|
  | `dish` (global) | 350 | every valid skill, `modelInvocable: false`, `userInvocable` from the skill | `dish-config`, or `dish-default` while the store is absent |
  | `dish-role` (agent layer) | 250 | the role's skills, invocation from the skill | as above |

  - A provider reads only `cwd` and `signal` from lookup options, never `scope`.
  - The `locator` is `{ commit: string | null, name: string }`.
  - Every candidate sets `invocation` explicitly.
- **No real-state side effects.** Tests use temp directories. Any live `dsh` run sets `DSH_HOME`, `XDG_CONFIG_HOME`, `XDG_STATE_HOME`, `XDG_DATA_HOME` and `XDG_CACHE_HOME` to scratch directories. Never touch `~/.config/dish` or `~/.dsh`.
- **Skill text is written in our own words.** obra/superpowers is MIT, so adapting it is allowed. `plugins/skills/defaults/NOTICE.md` carries the credit and the license. Never paste long passages.

## Review Focus

1. **Role filtering is real.**
   - An agent on the dish preset is offered only its role's skills.
   - The `skill` tool refuses a skill outside the role (Task 7 tests, against dsh's real registry).
   - An agent on another preset gets no model-invocable dish skills.
2. **A broken document never breaks agents.** A hand-edited, unparseable `SKILL.md` is left out of the catalog and reported as a problem, and the rest still serves (Task 6).
3. **`seed` with `replace` never overwrites an edited document** (Task 1). The prompts upgrade only touches documents that still match an old default (Task 3).
4. **The store missing or `LOCKED`.** The shipped defaults are served, and nothing throws (Tasks 6 and 7).
5. **Prompts and skills agree.** Every skill named in a shipped prompt exists, and each crew prompt names exactly its role's skills (Task 10).

## Task 1: `seed` replaces unedited defaults (`dish-config`)

**Files:**
- Modify `plugins/config/src/store/store.ts`: `seed`, and a `SeedOptions` type exported beside `WriteMeta`.
- Modify `plugins/config/src/index.ts` (the type export list) and `plugins/config/README.md` (one paragraph).
- Test: `plugins/config/test/store.test.ts` (new `describe('seed replace')`).

**Interfaces:**
```ts
export interface SeedOptions {
  /** Per path: lowercase hex sha256 of earlier shipped texts. A stored document with one of these hashes is replaced. */
  replace?: Readonly<Record<string, readonly string[]>>
}
seed(defaults: Record<string, string>, owner: string, options?: SeedOptions): Promise<CommitInfo | undefined>
```
`DishConfigService` already picks `seed`, so the new optional parameter reaches it with no other change.

**Behavior:**
- Validate `options.replace` up front (`INVALID`):
  - it must be a plain object;
  - every key must be a path in `defaults`;
  - every value must be an array of 64-character lowercase hex strings.
- Then, for every path: missing → written (as now); present and `sha256(text)` in `replace[path]` → overwritten; otherwise untouched.
  - Hash the stored text as UTF-8 bytes, exactly as read from `main`.
- One commit, as now, with subject `<paths>: <owner> defaults`.
  - With at least one replacement, the commit also carries the note `updated to the new defaults`, as the `Dish-Note` trailer through the same path `write` uses.
  - Check that `commitPrepared` accepts a `note`. If it doesn't, add it, as `write` does.
- Guard and validators run on the replaced documents too.
- `base: head`, as now. A document that changed in the meantime is a `CONFLICT` retry, never an overwrite.

**Steps:**
- [ ] Failing tests first:
  - a missing path is written and a matching stored path replaced, in one commit carrying the note;
  - an edited document (hash not listed) is untouched;
  - nothing to do returns `undefined`;
  - a `replace` key not in `defaults` is `INVALID`;
  - a malformed hash is `INVALID`;
  - existing seed tests stay green;
  - `history()` shows the note.
- [ ] Implement. Run `pnpm typecheck && pnpm test` and check the exit code.
- [ ] Commit `dish-config: seed can replace unedited defaults`.

**Details:**

- **History unavailable** (not a git repo, or a shallow clone where `git rev-parse --is-shallow-repository` prints `true`): `computePrevious` throws an error whose `code` is `NO_HISTORY`, so a drift test can skip.

```ts
export const SKILLS_PREFIX = 'skills/'
export const SKILL_FILE = 'SKILL.md'
export const SKILL_NAME: RegExp            // /^[a-z0-9]+(?:-[a-z0-9]+)*$/
export const ROLE_NAME: RegExp            // /^[a-z][a-z0-9-]*$/
export const SHIPPED_ROLES: readonly string[]   // main, architect, coder, reviewer, researcher, ops, writer
export const MAX_NAME = 64, MAX_DESCRIPTION = 1024, WARN_CHARS = 8000
export function isSkillName(name: string): boolean
export function pathFor(name: string): string              // throws on a bad name
export function nameFor(path: string): string | undefined  // inverse; undefined for anything else
export interface ParsedSkill { name: string, description: string, roles: string[] | null, modelInvocable: boolean, userInvocable: boolean, metadata: Record<string, unknown>, body: string }
export type ParseResult = { ok: true, skill: ParsedSkill } | { ok: false, problem: string }
export function parseSkill(path: string, text: string): ParseResult
export interface SkillCheck { problems: string[], warnings: string[], skill: ParsedSkill | null }
export function checkSkill(path: string, text: string, knownRoles: readonly string[]): SkillCheck
export function offeredTo(skill: Pick<ParsedSkill, 'roles'>, role: string): boolean   // roles null → true
export function validate(path: string, text: string): string | undefined              // the namespace validator: parseSkill's problem
export function namespaceSpec(owner: string): NamespaceSpec                           // { prefix: 'skills/', owner, agent: 'propose', validate }
```

**Parsing rules** (exactly the spec's):
- **Frontmatter delimiters.** The document starts with `---\n`, optionally after a UTF-8 BOM, and the frontmatter ends at the next line that is exactly `---`.
- **Line endings.** Normalize `\r\n` to `\n` before parsing.
- **YAML.** `js-yaml` `load` with the `JSON_SCHEMA` / core schema, so no custom types. The result must be a mapping.
- **The fields:**
  - `name` must equal the path's name;
  - `description` must be a string, non-blank after trimming, at most 1024 characters;
  - the body is everything after the closing delimiter, trimmed, and must be non-empty;
  - `disable-model-invocation` and `user-invocable` must be booleans when present;
  - `metadata` must be a mapping when present;
  - `metadata.roles` must be an array of strings matching `ROLE_NAME` when present.
- **Invocation:** `modelInvocable = disable-model-invocation !== true`, and `userInvocable = user-invocable !== false`.
- **Problems** read like `"skills/x/SKILL.md: description is missing"`: one sentence, and only the first problem found.
- **Warnings:**
  - over `WARN_CHARS` characters: `dsh may trim a skill this long when the context is full; keep it under 8000 characters`;
  - each unknown role: `role "x" isn't a role dish knows (main, architect, …)`.
