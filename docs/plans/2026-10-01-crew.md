# Crew Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the `plugins/crew` spike into `dish-crew`:
- `crew.yaml` in the config store;
- the `delegate` tool on the dish preset, with the reviewer family rule, follow-ups and limits;
- crew's own record and saved reports;
- role-named finish notices;
- the dish preset, which moves here from `dish-prompts`.

**Architecture:**
- **Host plugin.** `dish-crew` claims and seeds `crew.yaml` when `dishConfig` appears. It provides the `dishCrew` service, which serves the current settings and the record. It also captures every crew child's runs from `subagent/end` and `agent/error`.
- **Preset row.** `dish-crew/delegate` registers `delegate` and an `agent/pre-step` listener that rewrites crew children's finish notices.
- **Pure helpers** handle settings parsing, model choice and tool lists, so the rules can be tested without dsh.

**Tech Stack:** TypeScript (Node 24 type stripping, erasable syntax only), `node --test`, Cordis, dsh 0.2.0-rc.2, `js-yaml`.

**Spec:** [docs/specs/crew.md](../specs/crew.md). Read it first, then the spike (`plugins/crew/src/index.ts`), which this plan replaces.

## Global Constraints

- Everything from the prompts plan's constraints still holds:
  - erasable syntax only;
  - runtime imports of `@deepseek-ai/*` packages only when they're declared under both peer and dev dependencies;
  - tests in `<package>/test/*.test.ts`;
  - every task ends with `pnpm typecheck && pnpm test` passing and one commit;
  - **no dsh command against the real store or profile before Task 9.** Use scratch `DSH_HOME` and `XDG_*` directories, as in the implementer brief.
- **Work on branch `crew`**, cut from `main`. Humans merge.
- **Dependencies.**
  - `js-yaml` (^4.1, already in dsh's tree) is the one new runtime dependency, with `@types/js-yaml` as a dev dependency.
  - `dish-crew` depends on `dish-config`, `dish-prompts` and `dish-kit` (`workspace:*`).
- **Tool definitions** use `defineTool` from `@deepseek-ai/dsh-tools`.
  - Output schemas put `required: true` on each property; never use a JSON-Schema `required: [...]` array.
  - Empty strings in arguments are treated as absent.
- **Wording.** Every refusal is an `Error` whose message tells the model what to do next.
- **The never-list** is a single exported constant: `delegate`, `subagent`, `subagent_fork`, `subagent_codex`, `subagent_claude_code`, `list_subagent_models`, `workflow`, `ralph`, `interrupt_agent`, `list_agents`, `ask_user_question`, `create_goal`, `update_goal`, `exit_plan_mode`, `present`. (The last four delegation names were added in review.) `run_code`, dsh's reserved transport, is also never allowed, handled next to the list.

## Review Focus

1. **The reviewer can never run in the reviewed work's family.** This must hold for every path: defaults, overrides, `reviews: "main"`, follow-ups to a reviewer, and a reviewed child whose model was overridden.
2. **The limits can't be bypassed through `delegate`.** That covers the running, writer and per-session limits, follow-ups, a restart (the per-session count comes from the record), and concurrent calls in one step.
3. **A broken or missing `crew.yaml`, or a missing prompt, never starts a misconfigured child.** Every refusal says what to fix.
4. **The record never loses a run or a report,** including across restarts and for children resumed later. Notices from children crew didn't start pass through untouched.
5. **No child gets a delegation tool or a main-only tool,** whatever `crew.yaml` says.

### Task 1: Package, `crew.yaml` settings, host plugin skeleton

**Files:**

- Create: `plugins/crew/defaults/crew.yaml`, `src/settings.ts`, `test/settings.test.ts`, `test/plugin.test.ts`

**Interfaces:**
- **`CrewSettings`:**
  - `{ provider, families: Record<string, { strong, mid }>, reviewerFamilies: string[], limits: { running, writers, perSession }, roles: Record<string, RoleSettings> }`
  - `RoleSettings = { tier: 'strong' | 'mid', family?: string, writes: boolean, reviews: boolean, tools: string[] }`, where `writes` and `reviews` default to `false`.
- **`parseSettings(text): { ok: true, settings } | { ok: false, problem }`.**
  - Parse with `js-yaml`'s `load(text, { schema: JSON_SCHEMA })`, so no custom tags are accepted.
  - Then check every rule in the spec's Validation section:
    - unknown keys are refused at every level;
    - each family has both tiers;
    - `reviewerFamilies` lists only known families;
    - limits are positive integers, with `writers ≤ running`;
    - role names follow the prompts grammar (`^[a-z][a-z0-9-]*$`, and not `common` or `main`);
    - every role has a tier;
    - exactly one role has `reviews: true`, and it has no `family`;
    - every other role has a known `family`;
    - `tools` is a list of non-empty strings.
  - Messages name the path, e.g. `roles.coder.family: "antropic" is not a family (families: anthropic, openai)`.
- **The namespace spec:** `CREW_SPEC: NamespaceSpec` is `{ prefix: 'crew.yaml', owner: 'dish-crew', agent: 'write', validate: (_p, text) => problem-or-undefined }`.
- **Defaults:** `DEFAULT_TEXT`, read once from `defaults/crew.yaml`, and `DEFAULT_SETTINGS`, parsed from it. Loading fails if the shipped file doesn't parse.
- **The host plugin** `dish-crew`:
  - Config: `dataDirectory` (default `join(xdgPaths('dish').data, 'crew')`, absolute or `~/`), `subagentProvider` (default `spawn`) and `terminal`.
  - It provides `dishCrew` with `settings(): Promise<CrewSettings>`, which reads `crew.yaml` on main and falls back to `DEFAULT_SETTINGS`, logging once per distinct problem or absence. Task 4 adds `records`.
  - In `ctx.inject(['dishConfig'], …)` it claims `CREW_SPEC` and seeds `{ 'crew.yaml': DEFAULT_TEXT }`.
  - It logs as `dish-crew` through `printOwnLogs`.
- **`cordis.patch.yml`:** inserts `- id: dish-crew, name: dish-crew`.
- **The spike's config schema and roles are deleted.**

### Task 2: Families, routes and the reviewer rule

**Files:**
- Create: `plugins/crew/src/models.ts`, `test/models.test.ts`

**Interfaces:**
- **`familyOf(model, settings): string | undefined`.** The family whose tiers list the model. Otherwise a prefix fallback: `claude` → anthropic, `gpt`/`o<digit>`/`codex` → openai, `gemini` → google, `grok` → xai. Otherwise `undefined`.
- **`chooseRoute({ settings, role, override?, reviewed? })`** (changed in review: `reviewed: { model?, family? }`; the reviewer's exclusion is by family name *and* by vendor, so a model missing from `crew.yaml` or renamed families can't let a reviewer share the reviewed work's vendor) returns `{ ok: true, route: { provider, model, family } } | { ok: false, problem }`:

    - The family is the first entry of `reviewerFamilies` that differs from `reviewedFamily`, at the reviewer's tier.
    - An override is accepted only if its family is known and differs from `reviewedFamily`.
    - If no family qualifies: "no reviewer family differs from <family>; add one to reviewerFamilies in crew.yaml".

### Task 4: The record

**Files:**
- Create: `plugins/crew/src/record.ts`, `test/record.test.ts`
- Modify: `plugins/crew/src/index.ts` (`dishCrew.records`, run capture, prune at start)

**Interfaces:**
- **`CrewRecords`,** constructed with `(directory)`. Session directories are `sha256(parent session id)`. A pointer file `by-child/<sha256(child id)>` holds a child's session directory name, so a run can be filed after a restart.
- **Methods:**
  - `children(sessionId): Promise<ChildRecord[]>`
  - `addChild(sessionId, record: NewChild): Promise<ChildRecord>`. It assigns `n` as 1 plus the session's count.
  - `addFollowUp(childId): Promise<void>`
  - `endRun(childId, { stopReason, error?, closing }): Promise<{ report: string } | undefined>`. It writes `<n>-<role>-<run>.md` (closing text, or `(no closing message)`), appends to `runs`, and sets `last`. For an unknown child it returns `undefined`.
  - `lookup(childId): Promise<{ sessionId, record } | undefined>`
  - `prune(maxAgeMs)`
- **`ChildRecord`:** `{ id, n, role, title, model, family, reviews?, startedAt, followUps, runs: { endedAt, stopReason, error?, report }[], last: 'running' | 'finished' | 'failed' | 'stopped' }`.
- **Writing.**
  - `children.json` and the reports are written atomically (temp file, then rename, in the same directory). Directories are `0o700`, files `0o600`.
  - Writes for one session go through one queue.
  - A corrupt `children.json` is renamed aside (`children.json.corrupt-<time>`), logged, and started fresh. The per-session count then restarts, and the log says so.
- **Run capture** in the host plugin:
  - On `agent/error` for a child the record knows, remember the error message in memory, by child id.
  - On `subagent/end({ id, stopReason, lastAssistantMessage })`, call `endRun` with that error, then clear it. The closing text is the assistant message's text blocks.
  - Failures are logged and never thrown.
  - `prune(180 days)` runs at start.

  - follow-ups;
  - `endRun` writes the report and the run, including a second run;

  - an unknown child;
  - corruption is set aside;
  - concurrent writes to one session don't lose an entry;
  - the plugin captures an error and an end from emitted events into a real directory.

### Task 5: The `delegate` tool (preset row)

**Files:**
- Create: `plugins/crew/src/delegate.ts`, `test/delegate.test.ts`
- Modify: `plugins/crew/package.json` (`exports["./delegate"]`)

**Interfaces:**
- **The row** `dish-crew/delegate`: `name = 'dish-crew-delegate'`, `inject = ['tools', 'subagents', 'llm']`. It reads `ctx.get('dishCrew')` and `ctx.get('dishPrompts')` per call. Either missing is an error naming the plugin that isn't running.
- **The tool** `delegate`, with arguments and checks exactly as the spec's "The `delegate` tool" section, in that order.
  - **Running and writer counts:** this session's records whose `last` is `running` and whose agent is running (`ctx.agents.get(id)?.status === 'running'`). The record can say running after a crash, so both must agree.
  - **Concurrent calls:** guard the check-then-start against two calls in one step with an in-memory per-session lock around steps 4–7.
  - **`reviews`:** a crew child id from this session, passed as `reviewed: { model: record.model, family: record.family }`, or `"main"`, passed as `reviewed: { model: <the parent's current model> }`.
  - **A start that dsh refuses** because the tool filter names a tool the child can't restrict (`tools.restrict() names unknown global tool`) becomes a refusal that names the tools to remove from `roles.<r>.tools`.
  - **Start:**
    - Label: `${role} · ${model} · ${title}`.
    - Persona: `(await dishPrompts.persona(role)).prefix`.
    - Tool filter: `{ allow }` from `allowList`.
    - Agent options: `{ provider, model }`.
    - `maxDepth: 1`, provider from the host config.
    - Then `records.addChild`.
  - **Follow-up:** `ctx.subagents.sendMessage(parent, to, [{ type: 'text', text: task }], { signal })`, then `records.addFollowUp`.
  - **The route check** is the spike's `preflight`, plus `reasoningEffort` when set. Its error lists `crew.yaml`'s models.
- **Output:** `{ child, role, model, label }`, rendered as `started coder «add login» on claude-sonnet-5.5 (child …)`, or `sent a follow-up to …`.
- **The description** tells the model:
  - when to use `to` and `reviews`;
  - that it's notified when each child finishes, so it should end its turn instead of polling;
  - which roles exist (from the settings at registration; refreshed on each call's error messages).
