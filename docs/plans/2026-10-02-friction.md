# Friction Fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use subagent-driven-development (recommended) or executing-plans to carry out this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

> **One open question.** Task 5 runs only if you say yes to the spec's [question 2, option B](../specs/friction.md#questions-for-you). Question 1's recommendation is planned (Task 1); if you say no to it, Task 1's top-level rule becomes "the first and the newest prompt", and its long-chat test changes with it.

**Goal:** Build what the [friction spec](../specs/friction.md) describes:
- the judge's gate reads the real task: the main agent's first and latest prompts, a child's brief and its latest instruction, each cut in the middle;
- the shipped prompts say how this machine works (escalation, read-only home, fresh shells), and fix the main agent's habits;
- `{{model}}` in dish's prompts is the session's selected model;
- crew picks a reviewer whatever model the main agent runs on;
- optionally, the report guard takes a shorter message for a report.

**Architecture:** Four independent changes in three plugins. No new package, dependency, service, config row or stored document.
- `dish-judge`: `taskOf` in `src/gate.ts` and a `clipMiddle` helper.
- `dish-prompts`: three shipped defaults with their `previous.json`, and the persona row's listener in `src/persona.ts`.
- `dish-crew`: `VENDORS` and `avoided()` in `src/models.ts`, and, if approved, the report guard's default.

**Tech Stack:** TypeScript run by Node 24's type stripping (erasable syntax only), `node --test`, Cordis, dsh 0.2.0-rc.2 (`dsh-system-prompt` in the persona tests).

**Spec:** [docs/specs/friction.md](../specs/friction.md). Read it first, including **Checks**: the plan argues from them. The prompt texts there are the texts to ship, word for word.

**Interfaces (`src/gate.ts`):**
```ts
/** One message is cut to this many characters, by taking out its middle. */
export const MAX_PART_CHARS = 4000
/** The task is kept within this many characters; the first and the newest message are always in. */
export const MAX_TASK_CHARS = 8000
/** `text` if it is within `max` characters, else its first and last halves joined by `\n[…]\n`, within `max`, with no half of a surrogate pair left at either cut. */
export function clipMiddle(text: string, max: number): string
/** Unchanged signature. The task as the spec's "The judge's task" says. Never throws; `''` when nothing can be read. */
export function taskOf(agent: GateAgent, topLevel: boolean): string
// GateAgent's session header gains `readonly parentSession?: unknown`.
```

**Rules** (the spec, exactly):
- **Top-level:** the `user/message` events with `source.kind === 'user'` (`promptText`, as today), oldest first; one equal to the one before it is dropped; each `clipMiddle(…, MAX_PART_CHARS)`. The task is the first; then `[… N earlier messages left out]` if any were left out; then the newest ones that fit, in order; all joined by `\n\n`. A message between the first and the newest is added, newest first, only while the joined whole (separators and gap line included) stays within `MAX_TASK_CHARS`. The first and the newest are always in.
- **Child:** own events from `inheritedEventCount`. The brief is the first `user/message` with `source.kind === 'user'`, and of it the first non-empty text block, trimmed. The latest instruction is the last later `user/message` that has `source.kind === 'user'`, or `source.kind === 'agent-message'` with `source.senderSessionId === header.parentSession` (a string; with none, no `agent-message` counts). Its text is its text blocks joined by `\n`, trimmed, without a block matching `/^Agent \S+ sent a message:\s*$/`. The task is `clipMiddle(brief)`, then `\n\n` and `clipMiddle(latest)` if there is one.
- The `snapshotEvents` notes in the file header change to say the above; the "route dsh prefers" note stays.

## Risks to watch

- **A bigger judge request.** The task can be twice as long as before (8,000 characters). Watch p95 on Settings → Judge after the rollout; Jev's time limit is 2 s.
- **A wider task lets more through.** Only human and parent text is added, and the thresholds are unchanged; a child's instruction is from the parent that wrote its brief.
- **Stored prompts that were edited** on the VM keep their text, so the new sections don't reach them (the rollout says how to check).
- **The vendor table can only widen exclusions.** A token wrongly read as a vendor keeps a reviewer away from more families, never fewer, except for the accepted alias case.
- **The persona now patches after other listeners ran.** A listener inside the waterfall that reads the persona sections' text would see the preset's text. None in dsh 0.2.0-rc.2 or dish does; the preview calls `applyPersona` directly.
