# Judge Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `dish-judge`: the TypeSafe Jev client, `judge.yaml`, the decision log, a command gate on every shell call, the approval answerer (with crew children switched to `ask`), a result screen for injected instructions, `ask_judge` for every agent, and Settings → Judge.

**Architecture:**
- **Host plugin:** `dish-judge` provides `ctx.judge`, a Jev client with a timeout, response checks and a status. It claims `judge.yaml` with agent policy `none`, and writes a JSONL log.
- **Three host-level listeners guard every agent:**
  - `tools/pre-execute`, prepended: the command gate;
  - `approval/request`, prepended: the approval answerer;
  - `tools/post-execute`: the result screen.
- **A global tool:** `ask_judge`.
- **A page:** Settings → Judge, through its own Typert remote, plus dsh's `remote.credentials` for the key.

**Tech Stack:** TypeScript (Node 24 type stripping, erasable syntax), `node --test`, Cordis, dsh 0.2.0-rc.2, React 18 (client), `fetch`. No new runtime dependencies beyond what crew already uses (`js-yaml`).

**Spec:** [docs/specs/judge.md](../specs/judge.md). Read it first. The API facts are in [docs/research/2026-10-01-typesafe-jev.md](../research/2026-10-01-typesafe-jev.md).

## Global Constraints

- **Carried over from the crew plan:**
  - erasable syntax only;
  - runtime `@deepseek-ai/*` imports only from packages declared as both peer and dev dependencies;
  - services the code doesn't inject are read with `ctx.get(...)`, never as a property. Test stubs are provided from **sibling** plugins, so a property read fails in tests as it does in dsh;
  - `defineTool` output schemas put `required: true` on each property;
  - empty strings mean absent;
  - every refusal tells the model what to do next;
  - tests live in `<package>/test/*.test.ts`;
  - each task ends with `pnpm typecheck && pnpm test` passing and one commit.
- **Work on branch `judge`**, cut from `main`. Humans merge.
- **No real TypeSafe calls in `pnpm test`.** Tests use a fake Jev: a local `node:http` server in `test/helpers.ts` that returns canned, slow or malformed answers and records requests. Live calls (added 2026-10-01, at your request) live in `plugins/judge/test-live/*.live.ts` and run only with `pnpm --filter dish-judge test:live`, with the key from your gitignored `.envrc`; they skip without a key and never print it.
- **Nothing touches your real store or profile, and no real key is used, before Task 10.** Scratch dsh runs use the `live6` pattern.
- **Keys are secret.** The key is read only through `ctx.credentials.resolve(keyName)` on each call. It is never logged, written, returned to the page, or put in an error message.
- **Prepended listeners.** Register them with `{ prepend: true }` where the spec says so. The command gate and the approval answerer must run before the browser's answerer.
- **Fail closed.** Every Jev failure (no key, a timeout, a non-2xx status, a malformed answer, a network error) is `ok: false`. The client calls a server `400` or `422` `invalid` (see Task 2) and the rest `unavailable`; callers treat every `ok: false` alike as unavailable. Gates then ask (for the main agent) or deny (for a child). Nothing runs on an unavailable judge.

## Review Focus

1. **A crew child never waits on a human.** Every approval request from a child is decided by the judge, which never calls `next()` for a child, including when Jev is unavailable.
2. **Gates fail closed.** No Jev failure lets a gated command run without either a confident verdict or you.
3. **Screening never drops content silently.** Withheld content is replaced by a note and kept in the log; when Jev is unavailable the content is marked "not screened".
4. **Agents can't see or change `judge.yaml`.** The key never reaches the log, the config repo, the page or a model. The log masks secrets.
5. **Bounded.** Every gate finishes within `timeoutMs` plus a small overhead, and no step hangs on the judge. Caches and the log are bounded.

## Tasks

> **Where a task's interfaces below differ from the code, the spec and the code are current.** The plan was written before the build, and the build changed these, among others:
> - **The client:** `400` as well as `422` is `invalid` (with `from`, `tooBig` and, for a private key, `opaque`). `createJudge` takes `{ baseUrl, key, settings, log, now?, tick?, maskSecrets? }`, and `ask` takes `tool`, `callId`, `subject` and a `decide` hook. `status()` also has `lastErrorAt`, `calls` and `failures`.
> - **The log:** `withhold({ tool, content }, { signal }?)`, and `read` returns `{ lines, next, skipped }`.
> - **The gate:** `commandGate(deps)`, where `deps` is `{ judge, settings, workspaceRoot?, cache }` and the client writes the log line. The cache is keyed by agent and call id. `cwd` is the call's `workdir` when it names one, else the session's.
> - **The answerer:** `childPolicy` switches only crew children whose parent is at `ask`.
> - **The screen:** `resultScreen(deps)`, in calls of at most 90 KB of state each, with one log line per call and not one per result.
> - **`git push --dry-run` runs** (Jev reads it as read-only), so it is `git push` that asks.

### Task 2: The Jev client

**Files:**
- Create: `plugins/judge/src/client.ts`, `test/client.test.ts`, and a fake Jev server in `test/helpers.ts`.
- Modify: `src/index.ts`, to provide `ctx.judge`.

**Interfaces:**
- **`createJudge({ baseUrl, key: () => Promise<string | undefined>, settings: () => Promise<JudgeSettings>, log, now? })`** returns the spec's `Judge`.
- **`ask` steps:**
  1. Check the questions:
     - choices have 2–255 options;
     - scores have 2–10 levels;
     - instructions are non-empty;
     - question ids match `^[a-z][a-z0-9_]*$`;
     - `state` is at most 100 KB of JSON.
  2. Resolve the key. If there's none, the result is `unavailable` with the spec's message.
  3. `fetch` with `AbortSignal.any([signal, AbortSignal.timeout(timeoutMs)])`, plus `redirect: 'error'`.
  4. Map the HTTP status:
     - `401` → `unavailable` ("the TypeSafe key was refused")
     - `422` → `invalid` (with the body's text, trimmed)
     - `429`/`529` → `unavailable`, and skip Jev until `retry-after` passes (default 5 s)
     - other non-2xx → `unavailable`
  5. Check the response as the spec says. A malformed response is `unavailable`.
  6. Write one log line for every outcome (Task 3's `log.write`; Task 2 takes `log` as an injected function).
- **`status()`:** `{ keySet, state: 'ok' | 'unavailable' | 'no-key', lastError?, lastOkAt?, p50, p95 }` over the last 100 calls.
- **The key** is never stored past the call, and never appears in an error or a log line. A test sends a key and checks that every log line and error string is free of it.

### Task 4: The command gate

**Files:**
- Create: `plugins/judge/src/gate.ts`, `test/gate.test.ts`
- Modify: `src/index.ts`, to register the gate

**Interfaces:**
- **`commandGate(judge, settings, log)`** returns a `tools/pre-execute` listener, registered with `{ prepend: true }` on the host context. For tools not in `tools.gated`, for PTC `run_code`, and when there's no `exec.agent`, it calls `next()`.
- **State:**
  - `command`: from the tool's arguments; check the installed bash/pwsh argument schema.
  - `cwd`: `agent.session.header.cwd`.

  - `task`: up to 4000 characters.
    - For a top-level agent, the latest user message in its session. Read it from the session events; find the API with `session.snapshotEvents()` or the turn's input, and document it.

### Task 6: The result screen

**Files:**
- Create: `plugins/judge/src/screen.ts`, `test/screen.test.ts`
- Modify: `src/index.ts`

**Interfaces:**
- **`resultScreen(judge, settings, log)`** returns a `tools/post-execute` listener. It is **not** prepended, so it sees the full content after the spill policy.
- **Matching:** `tools.screened` entries are exact names, or a prefix ending in `*` (`mcp__*`). Error results pass through.
- **Content:**
  - For native results, the text blocks are joined, chunked at `chunkChars`, and sent as one call with one noul per chunk (`injected_0`, `injected_1`, …).
  - Non-text blocks, such as images, are left out of the state and kept in the result.
- **The highest P across chunks** decides:
  - **≥ `withhold`:** the content is replaced by the spec's note, and `log.withhold(content)` keeps the original. The note gives no id to the model.
  - **≥ `warn`:** the spec's banner is prepended as a first text block.
  - **Unavailable:** the "Not screened" banner.
  - **Lower:** unchanged, as the same objects.
- **PTC inner calls** (`exec.parent` set):
  - **withheld:** `{ kind: 'block', feedback: [note] }`;
  - **warn or not screened:** `accept` with the value unchanged, plus `additionalContexts` carrying the banner.
- **Logging:** one log line per screen. The subject is `<tool> (<n> chars)`.

- [ ] **Step 1: Write the failing tests:**
  - withhold, warn, pass and not screened;
  - multi-chunk, where the highest wins;
  - `mcp__*` matching;
  - an error result is untouched;
  - images kept;
  - the PTC value paths;
  - the withheld content is stored and masked;
  - the note doesn't leak the content.
